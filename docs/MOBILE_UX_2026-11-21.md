# Mobile UX implementation and QA — 2026-11-21

## Scope and preservation

This update implements the three agreed improvement phases for the existing React/Vite portfolio. No content, unverifiable claims, background service, account connection, or new visitor tracking is added. Desktop's fine-pointer cinematic scene, site routes, dark/light themes, and Persian RTL remain supported.

## Phase 1: find work faster on phones

- Mobile, touch, and reduced-motion visitors see the portfolio immediately rather than a decorative first-visit boot sequence. The desktop first-visit animation is preserved.
- The hero uses responsive typography and a shorter layout; technical identity and the **Projects / Download CV** CTAs precede the two portfolio-relevant statistics on narrow screens.
- A one-tap accessible Search control is added to the small-screen top navigation.
- The five large bottom-nav entries become Home, Projects, Skills, Contact, More. Experience and Education remain in More. Safe-area and keyboard handling are retained.
- Enlarged project-filter, clear, source, refresh and navigation touch targets, with better mobile text sizes.

## Phase 2: less duplication, more evidence

- The accessible mobile flagship showcase stays as ordinary flow cards, with no desktop 3D on touch devices.
- The three repeated featured projects appear as compact, source-linked shortcuts in the main catalog on mobile, while desktop detailed cards and all 11 project anchor IDs remain intact.
- HiringTrail uses a shorter mobile recruiter path, preserving its full desktop evidence trail.
- Case studies expose a sticky horizontal table of contents for architecture, decisions, evidence, and limits.
- Architecture modal offers the mobile-readable written explanation and a deliberate opt-in to full Mermaid diagrams; rendering is skipped until requested on small screens.
- Skills link to *related* source-backed case studies. These are examples, not claims that every listed skill is independently certified.

## Phase 3: trustworthy polish and performance

- Cleaner section spacing and readable tags on narrow screens; responsive RTL case-study navigation.
- Reduced background particle count and draw frequency on coarse/small displays. Desktop particle rendering is unaffected.
- Mobile skill-map graph is hidden instead of loading ahead of key skills; full graph stays available on larger layouts.
- Lazy below-the-fold sections retain on-scroll, hash, and accessible manual mounting; mobile idle fallback loads after 18s rather than 6s.
- Each of the three case studies has a generated 1200x630 social image and path-specific Open Graph/Twitter metadata; no fake deployment claims or unverified metrics.
- White-on-transparent AK icon is retained in dark color scheme; a background-free dark monogram is provided for light browser tabs.

## QA to reproduce

Install project dependencies with `npm ci`; then run `npm run lint`, `npx tsc --noEmit -p tsconfig.app.json`, `npm run test`, `npm run build`.

Run `npm run preview -- --host 127.0.0.1 --port 4173`, then `python scripts/mobile-ux-smoke.py --base http://127.0.0.1:4173` (requires `playwright` plus its Chromium browser).

Manual checks should cover Android Chrome, iPhone Safari, 200% text zoom, hardware keyboard, reduced motion, light/dark mode, Persian and English, Safe Area insets, and a slow connection. Browser desktop emulation cannot certify actual-device touch behavior, 75th-percentile Core Web Vitals, or iOS Safari behavior; no such claims are made.

The 3D desktop scene and 11 GitHub-backed project records should remain intact. No code should be merged if CI fails.
